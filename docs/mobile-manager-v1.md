# 手机总管首版：接着原来的事做

2026-11-24 · 产品目标与跨端架构设计。已实现和已验证的范围见[首版验收记录](roadmap.md#mobile-manager-v1)。

2026-11-25：用户确认把手机端扩为个人助手，下一阶段的定位、范围和设计见[手机个人助手](mobile-assistant-v2.md)。本文仍是已交付首版的设计依据；「谁负责回答，谁能确认执行」「如何把话交回原项目」「让等待可理解」三节的规则在下一阶段继续适用。

## 首版体验目标

1. **打开手机就能说事。** 默认入口就是和总管对话。用户可以提新需求，也可以说“接着聊昨天那个方案”。总管能确定是哪段讨论，就直接接上；确实有歧义时，再给用户少量选项。按项目、最近使用、分类浏览会话的入口仍然保留，用户想自己找时也找得到。
2. **电脑全关，手机也有独立价值。** 手机侧常驻的 DeepSeek 能正常对话、搜索，也能完成适合手机的内容制作，比如把讨论整理成提纲或起草一段文案。用户不需要先弄清哪台电脑在线，才能开始做事。
3. **需要电脑时，总管负责衔接。** 首版对接 Codex 和 DSH。需要它们执行的工作，由总管找到对应项目或会话，把任务交过去，再把进展和结果带回当前对话。用户不用为了发一个任务，在手机上逐层找项目、选工具、翻会话。
4. **回应要快，状态要真。** 用户发完消息，总管马上回应自己理解了什么、现在能做什么；同步电脑在后台进行。只有确实收到执行端反馈，才显示“已开始”。你想消除的是发完消息后“不知道有没有收到”的空白感，而不是用一句“正在处理”掩盖电脑离线。

## 使用场景与价值

首版服务于交替使用手机和电脑、手里有多个项目和会话的人。用户只需告诉星引「我想继续哪件事」：能在手机完成的，当场做完；需要电脑的，由总管组织交接、跟进并带回结果。成功的标志是少翻一次会话、少讲一遍背景，而且事情没有交错或遗漏。

例如，电脑都关了，用户说「继续昨天的登录页讨论，按钮文案再短一点」。星引打开已同步的原讨论，说明所依据的最近记录，给出文案。用户选定「继续」后，这项决定留在讨论中。此时没有派工。用户再说「把它改到登录页」，看到目标项目和原会话，确认交给电脑。此后用户可以退出这场讨论；回到手机时，能从总管看到这件事在等哪台电脑、是否需要自己处理，以及改动的结果。

| 入口或时刻 | 用户看见什么，能做什么 |
| --- | --- |
| 打开 App | 首屏就是总管对话，输入框直接可用。「继续上次讨论」或一条需要处理的事项可以就地打开；没有事项时不摆空面板。未配对电脑不阻断手机助手，首次缺少 DeepSeek 配置时只引导完成当前需要的一步。 |
| 提到已有工作，或想开讨论 | 唯一可靠匹配就打开相应讨论或会话；有歧义时只给少量候选，显示项目、来源和最近主题。用户也可以直接开一场项目讨论。打开、阅读和讨论都不自动向电脑发送。 |
| 想自己找 | 同一「找会话」入口可按项目、最近使用、分类浏览。分类先区分总管对话、项目讨论、Codex 和 DSH 原生会话；保留未归类项。三种视图和总管打开同一条记录；重新同步不应把老会话顶到最近。 |
| 从讨论转为执行 | 在原对话显示要做什么、发往哪里、需要的权限；用户对这个目标明确开工即可。同一处呈现等待原因、待答问题和结果摘要，可点回原讨论、原会话或产物。正常路径不要求学习调度模式或先去设备页。 |

**这次转向的依据。** [桌面同题对照](roadmap.md#standard-first)中，一次带质量标准的团队交付用了 90.0 分钟，单人用了 33.7 分钟；随后的匿名择优探针三次均选原单人版。该样本没有证明团队稳定优于单人。用户据此决定停止以多 Agent 自循环提升能力为开发主线。保留总管管理多个独立工作、按需开讨论的能力；已交付的桌面实验及历史结果保留。新首版不以增加轮次、参与者数量或胜过单个模型为目标。

## 谁负责回答，谁能确认执行

用户面对一个总管。手机可以独立回答和记录决定；只有目标电脑能确认本机工作是否已开始、改了什么。两者用有来源的消息和回执衔接，不需要一个全天在线的中心服务器。

| 边界 | 首版职责与取舍 |
| --- | --- |
| Android 客户端与手机 DeepSeek | 安卓原生层用系统密钥库保护用户配置的凭据，从手机直连不依赖任何一台电脑的 DeepSeek 服务。总管可以流式对话、按需联网搜索并给出来源与检索时间，在当前讨论生成、保存和复制文案、提纲等文本。先支持文本成果；修改电脑文件交给桌面端。手机没有模型网络时仍能浏览本地记录、保存草稿；搜索不可用时说明原因，不编造来源。 |
| 手机本地存储 | 保存总管对话、项目讨论中的手机消息与决定、授权范围内同步的会话名片/近期摘录、待发命令和接收进度。摘录显示来源、同步时间和缺口；没有同步过的正文不能凭标题补写。上下文只取本轮所需的讨论、决定和用户选中的材料，用户可看见哪些材料会交给模型。 |
| 配对与同步 | 借用迁入 R3 的设备身份、配对和协议约束。首选已配对设备间直连，需要时才经可用的加密中继；中继只转发，不运行总管或代存待办。桌面新增面向已配对手机的连接入口，将有限的查询、命令和事件接入现有 Hub；不把 Electron 的内部 IPC 或 SQLite 暴露到网络。手机和电脑各存自己的账本，按来源事件序号增量同步、断点补齐，不复制运行中的数据库。 |
| 桌面 Hub 与连接器 | 复用项目账本、讨论交接、权限、同目录占用、调度和回执核对。新受托工作沿用桌面的 DSH 默认，可明确选 Codex；继续已有工作保留绑定的执行端，原生会话续聊交其原 owner/Host。目标不兼容或 owner 离线时显示原因，不偷偷换会话。Codex 原窗口续聊与 DSH Remote 桥分别验证；DSH 原 Host 缺少按回合停止的接口时不提供该动作。 |

「手机常驻」指打开 App 就可用，所有电脑关机时也能通过手机网络使用 DeepSeek；不要求手机本地运行模型，不承诺 Android 杀掉 App 后仍会推理或送达。手机与电脑恢复连接且 App 获准运行时才处理本地待发。已被桌面接受的工作由该桌面继续，结果待手机重连补回。只有经办公电脑转发才能访问的网关不满足独立运行条件；不预设已有可用账户、搜索权限或中继部署。

## 手机文件、照片与正文排版（2026-11-24）

手机总管可以在对话中选择模型及思考强度。默认官方 DeepSeek V4.1 Flash（接口名 `deepseek-flash`）/ High；支持 Low、High、Max、关闭思考。同一配置用于文字和附件，不覆盖已有自定义网关。选中材料时不得丢掉附件后按纯文本发送；模型能力不匹配须明确说明。ZIP 先在本机读取目录、受限长度的文本和支持的图片，列清没读到的条目，不执行归档中的文件。

V2338A 已由用户确认微信「用其他应用打开」能显示文件名且副本正确。第一版此后发出的实际消息没有附件引用，同一讨论已有一个 ZIP；仅收件不代表总管已读。后续收件默认进入下一轮待发选择，保留取消勾选，点击发送才交给模型；模型未实际返回前不记验收通过。

用户希望从微信、QQ 和相册带入材料，在当前讨论阅读或交给电脑办理；文字成果要适合在手机上读。**排版由程序负责**：手机根据返回的原文显示段落、标题、列表、引用、表格和代码。无标记的长段中文可在完整句子之间留出段距，不补写标题或结论。讨论记录、回执依据和复制的 Markdown 保留原文；排版不需要模型或网络。Markdown 产物按文档预览，源码和差异保留原样。

**已实现并隔离验证：** 手机页面样例使用固定样本文本；生产页面通过流式显示、重开、窄屏表格、任务回执、Markdown 产物和逐字复制检查。Android 调试包构建、lint 与签名检查通过。本项未在真机安装验收，未更改模型提示词或调用真实模型。

用户要求从星引当前讨论发起，选择微信「文件传输助手」里的文件，无需先另存或从微信反向分享。例如选好报价单，再从相册加一张手写说明，问「付款条件是什么」；需要核对项目时再点「交给电脑」。微信和 QQ 首选来源应用的「用其他应用打开」；图片在微信保存后从系统相册选择。QQ 不同版本的入口及带附件的电脑派工仍需分别验证。

**当前交互。** 微信、QQ 文档优先用「用其他应用打开 → 星引」。星引收到临时授权即复制到本机收件区，再由用户选择接收讨论。可以稍后归入，或丢弃尚未归入的本机副本；重开后未处理的收件仍可领取。「收到文件」显示文件名、大小、类型和本轮勾选项，可放进新讨论、输入要求或一键总结。已接入系统相册及本机文件选择，小程序和微信 SDK 已移出默认包。普通文字沿用系统粘贴。

**微信小程序备选。** V2338A 上官方 DeepSeek 2.9.0 的「微信文件」经微信小程序进入会话选择页；未观察其后台实现。已有星引小程序代码使用[Android OpenSDK 拉起接口](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Launching_a_Mini_Program/Android_Development_example.html)和[微信会话文件选择器](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.chooseMessageFile.html)，未登记或上线，不是手机本机收件的依赖。

历史小程序方案在当前讨论打开一次导入；手机持有领取凭据，小程序只收临时上传凭据。用户勾选并确认后才上传到专用 HTTPS 中转，手机回到前台取回已完整提交的一批文件，保存本机副本并绑定发起讨论，再确认清理中转。每批最多 3 份，每份 4 MiB，10 分钟过期；单用户中转只在内存短存，重启后须重选。不借用微信账号、DeepSeek Key 或桌面配对凭据签发导入任务。导入不派工也不调用模型；用户在讨论里选择文件并提问后才送模型。接入参数、运行方式和真机验收见[微信导入](../mobile-app/wechat-import/README.md)。

**手机本机是优先入口。** 电脑关机、没有微信小程序登记也应能在星引选手机文件、选相册照片、在输入框中粘贴文字。Android 选择器只授权所选内容，星引流式保存到手机私有目录，每批最多 3 份、每份最多 20 MiB。外部「分享／用其他应用打开」明确选择接收讨论；从星引主动选择则绑定发起讨论。导入不上传、不派工；可先在本机打开，发问才使用已配置的官方模型。vivo 文件管理器有微信文件分类，但第三方选择器能否返回尚未另存的文件取决于系统和微信，不能标成已支持读取聊天记录。微信专属小程序仅保留参考工程。

| 2 · 让总管读到内容 | 先做 TXT/MD 和常见照片。官方 [DeepSeek 图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)已明确支持 `deepseek-flash` 看图。手机用用户已配好的官方 Key，图文同一条消息发送（`text` 和 `image_url` 内容块）；本地照片可用内联图片，不需要公开图床或让 OCR 先转文字。与现有纯文字会话分开选择能收图的模型；自定义网关按实际能力。PDF、Word 等按[官方文件接口](https://api-docs.deepseek.com/zh-cn/guides/files_api/)公布的格式或本地提取方案接入，保留材料及出处；扫描件可用[官方 OCR](https://api-docs.deepseek.com/zh-cn/guides/ocr/)。材料只作资料，不构成开工授权。 | 电脑全关、手机联网，分别核对截图里独有的金额和照片中没有文字的图形关系；检查未勾选的图没进请求。文件传输助手另用未另存的文件从星引发起，核对导入内容和原讨论；取消不留附件。文件不可用、截断、模糊或不支持时说明，不声称已读。 |
| 3 · 把选定材料随任务分发 | 复用已配对手机到 Hub 的 HTTPS 连接，新增项目范围内的二进制流式上传；不把 Base64、手机 URI 或绝对路径塞入聊天或派工 JSON。上传完整后，Hub 复用现有附件副本，返回与设备、项目绑定的附件 ID 和版本。交接卡列出目标、所选文件及发送原件还是摘录；命令引用该版本。托管任务走已有附件参数；原会话首期传带出处的正文摘录，不承诺原件。需要原图而目标不支持时说明原因，不替换会话。 | 在已选目标上授权一次。上传中断则补传或重传同一附件；命令可能送达时只核对原请求，不重复派工。分别测 Codex 和 DSH，同名文件不串、跨项目引用被拒、撤销后不派工；原讨论区分「已保存」「电脑已收到」「本回合已传入正文／图片／仅文件信息」。 |
| 4 · 带回可用成果 | 结果沿用原讨论、原回合与产物版本。手机直接排版回复；需要独立文件时，提供保存 UTF-8 `.md` 和系统分享，保留正文及材料出处。 | 核对回执、手机预览、复制及导出文件；复制/导出内容一致，无额外模型调用。电脑离线仍能看手机已存的正文。 |

当前基线：[Android 材料读取](../mobile-app/android/app/src/main/java/app/alcor/mobile/DiscussionFiles.java)、[本机 ZIP 阅读](../mobile-app/android/app/src/main/java/app/alcor/mobile/ArchiveInput.java)、生产收件面板样例。ZIP 读取受支持的 UTF-8 正文（每项 96 KiB、整包文本 160 KiB）及首张不超过 4 MiB 的受支持图片；其余列名，不执行源码。PDF、Word 用官方 Flash 文件解析，超出所选模型能力时明确提示，不擅自换模型。

资料分发实施边界：交接卡冻结最多三份材料；同一次授权按「请求编号 + 材料序号」上传，可在未发出任务时重传同一副本。Hub 核对设备、项目、授权有效期和材料总数，收到全部匹配版本后才登记任务。修改未发送的授权会创建新请求。托管 Codex 可收受支持的文本文件和图片，托管 DSH 可收文本文件；托管执行时每个文件最多传入 30,000 字符正文。ZIP 只发有出处的文字摘录，不发归档原件或归档图片。两种原会话仅收最多 2,500 字符／份的文本摘录；需要图片或其他二进制原件时明确拒绝，不用文件名冒充内容，也不换执行端。手机分别显示电脑收到的份数、执行回合实际收到了正文还是图片，以及正文是否截断。此限制不改变手机用官方模型阅读本机文件的能力。

成果导出边界：手机回复、桌面回合正文及文本产物可用 Android 文件选择器保存 UTF-8 Markdown，或用系统分享发送同一份文件。导出内容保留原文，并在末尾记录当前讨论及所知的材料或回合出处；单独的「复制」仍保留原文。「复制导出内容」和保存、分享使用同一文本，不调用模型。手机可离线打开最近预览过的 4 份桌面文本产物；本机副本绑定原任务、回合证据与产物，缺副本时明确提醒，收到新版本后不把旧副本当新结果。

2026-11-24 验证：Android 包已通过 lint、构建、签名并升级至 V2338A，保留了原讨论和 ZIP。真机本地预览读到 8 份正文、1 张待发图片；用户点击发送后，16:39 的消息带 1 个附件引用，收到完整格式化答复，交叉核对发现材料正文中独有的词句。未记录文件名和内容。隔离 Android 36 模拟器额外核对系统文档、照片选择器与可读副本，以及 Android 实际请求构造中的模型、思考强度、ZIP 文本和图像块；不支持图片的官方模型被明确拒绝。

## 如何把话交回原项目

1. **定位。** 同步时复用稳定的项目、讨论、设备和原生会话身份；原生引用包含提供方、连接器实例、环境/账户与原生会话 ID。总管和手动列表共用同一索引；用户更正及原生归属优先，按目录推断的低置信候选不能作为自动派发依据。同名、失联和跨设备路径都不按标题合并。
2. **保留上下文。** 手机与桌面上的同一星引讨论共用讨论 ID。离线新增的消息以来源和消息 ID 合并，双方新发的消息都保留，不按最后写入覆盖整段历史。明确决定引用用户原话和所依据的版本；像「这次按钮用『继续』」这样的选择随本项工作交接，只有明确适用于整个项目的决定才由桌面核对版本后写入规则账本。同一决定在两端被改过时保留双方版本，请用户只选冲突的那一项。手机围绕原生会话做的草稿和讨论保留对原会话的引用，不能伪装成原生历史。
3. **明确交接。** 交给电脑的是一份带稳定请求 ID 的命令，绑定来源讨论、目标设备与项目、原会话或明确的新建目标、任务/规则版本、授权范围及验收条件。附用户选定的决定与必要摘录，不整库上传。已选目标上的明确发送就是授权；「接着聊」、只看进度和仅认可文案都不算开工。模型可建议目标，不能自行生成路径或扩大权限。
4. **返回原处。** Hub 用同一请求 ID 入账去重，校验目标、版本、权限和占用后才调用对应连接器。回执关联工作、原生会话及回合；产物与待答问题沿原关联回到讨论，总管显示摘要和入口。两处展示引用同一结果，重连补事件不再发一遍消息或启动第二个回合。

## 让等待可理解

手机先持久保存输入并立即显示，DeepSeek 的实质答复不等待桌面同步。需要电脑时，同一条消息显示以下状态；总管可以同时回答能在手机完成的部分。

| 已有证据 | 手机显示与下一步 |
| --- | --- |
| 只保存在手机，尚未尝试发送 | 「已记下，等电脑上线」；可修改或撤销。重连核对身份、授权、版本和有效期仍相符，才发送当前有效的命令。过期、目标变动或撤销不派发。 |
| Hub 已登记，已知仍在排队 | 「电脑已收到，等待执行」；不显示执行中。若有目录占用，说明正在等哪项工作。 |
| 可能已送出，但缺少匹配回执 | 「送达待核对」；先按原请求查 Hub 和原生证据。未知期间不新建请求重发，不把取消请求写成已停止。 |
| 原执行端确认对应回合开始、结束或失败 | 有开始证据才显示「执行中」；结束后附结果或失败原因。需验收的结果显示「待验收」，通过约定检查或由用户核对后才显示「已完成」。 |

## 如何接入现有项目

### 首版实施选择

- Android 使用独立应用 ID，保留原 DSH 远程应用及其数据。生产 WebView 只加载内置页面，沿用网页原型的手机样式和图标；网络、原生剪贴板、Android Keystore 凭据和原子落盘由 Java 宿主处理。
- 手机使用 DeepSeek Chat Completions（官方或手机可直达的 HTTPS 网关）。使用官方端点时，同一把 Key 用于 [DeepSeek 官方 Search API](https://api-docs.deepseek.com/guides/search/)；自定义网关不把模型 Key 发给搜索服务，可单独配置 Brave Search。来源只来自实际检索结果，失败时保留原请求并显示原因。
- 桌面首版先提供直连：在设置中选择共享的项目与局域网地址，生成一次性配对码。手机校验该码内的桌面 TLS 证书指纹；Hub 只暴露项目范围内的手机协议，支持单独撤销设备。跨网络转发不作为直连验收的前置。
- Android 重连先查已可能送达的请求编号；Hub 已登记的请求由 Hub 去重。Hub 在调用原生端之前持久记录派发意图，重启后只核对原有收据。手机不能以空回执、网络恢复或旧缓存推断已开始。
- DSH 同一桥地址轮换凭据时，旧授权不能用于新发送。已经尝试发送的原请求，可用该桥当前凭据只读核对；须匹配原项目、原会话、请求编号和发送内容，才把更新后的回执带回原讨论。
- 托管工作的文本产物可从原讨论的当前回执预览；Hub 按工作、回合和文件版本核对。原生会话只回传已核实的回合正文和原会话入口；有结束证据但对应历史尚未同步时，暂不开放手机验收。

- **桌面起点：** [讨论与派工](../desktop-app/src/hub/agents.ts)、[项目决定](../desktop-app/src/hub/project-decisions.ts)、[连接器](../desktop-app/src/adapter/)和[桌面回执边界](architecture.md)。桌面保有任务与执行事实的写入权；手机不另建一套电脑调度器。
- **手机起点：** 原 Android 客户端有会话、同步和待发基础；[R3 身份与可靠执行](r3-design-baseline.md#r3-state-reliability)及[总管设计](r3-design-baseline.md#r3-orchestrator-entry)是复用依据。原方案的「先汇报再输入、首期只找续、派工后置」由本设计调整为「对话首屏、单次授权派工进入首版」；不把旧 APK、原型或既有 Relay 的能力当成本次端到端验收。
- **交互原型：** [网页原型](../mobile-app/prototype/README.md)按本文四个体验目标给出 10 个可点击场景、状态文案与图标，用于对齐交互；回执由页面模拟，不代表已实现。
- **验收前要实测：** Android 真机在无电脑参与时能否访问选定 DeepSeek 和搜索服务；配对传输、跨端讨论合并、两个执行端的原会话接续及丢回执恢复。实施顺序和通过条件见[开发路线](roadmap.md#mobile-manager-v1)。
