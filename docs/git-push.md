# 公开版推送规则

公开仓库的 `main` 保存别人可以从干净检出构建和试用的版本。内部开发和公开发布分别维护；每次只把核对过的内容同步到公开分支。

## 小阶段验收就可以推送

完成一个能独立验收的功能或修复，就可以把这一阶段推到公开 `main`，不用等下一阶段、另一个平台或所有预览能力完成。每次写清「改了什么、怎么复验、还有什么限制」。只合入这一阶段需要的改动。

| 范围 | 推送条件 |
| --- | --- |
| 产品功能或修复 | 用合成数据跑通本阶段的用户场景，并通过受影响平台的构建和核心回归。改配对、回执或数据格式等跨端契约时，验证受影响的两端及兼容性。核心场景回归时先修复。 |
| 预览功能 | 可以推送。README 或发布说明写明需要的配置、测试到哪一步、哪些路径尚未验收。它的失败不得阻断核心流程或破坏已有数据。 |
| 仅文档 | 检查内容和引用即可。 |
| 新的外部依赖或素材 | 记录用途、依赖版本和许可证。公开版本默认要求用户配置自己的账号；示例和测试只用占位值或合成数据。 |
| 安装包 | 只有重新从同一公开提交构建并验证过才发布。说明平台、签名或调试状态；安装包和诊断记录不进源码历史。 |

## 版本号与发布标签

源码推送和版本发布分开。小阶段可以持续推源码；只有要把一个版本作为独立交付（例如发布安装包或可引用的源码版本）时，才更新对应平台的版本号、写发布说明并打标签。一批小阶段可以合成一个版本。Windows 和 Android 独立编号。

| 变更 | 规则 | 示例 |
| --- | --- | --- |
| 修复或不改变兼容性的改进 | 递增补丁号 `X.Y.Z` 的 `Z` | Windows `0.2.1 → 0.2.2` |
| 新增或明显扩展一项可用能力 | 递增次版本号 `Y`，`Z` 归零 | Android `0.1.0 → 0.2.0` |
| 不兼容的接口或数据格式变化 | `0.x` 阶段递增次版本，说明迁移和回退；从 `1.0` 起递增主版本号 `X`，其余归零 | `0.2.2 → 0.3.0`；`1.2.3 → 2.0.0` |
| 单独发预览版 | 在目标版本后加 `-preview.N`，同一目标版本从 `1` 递增 | `0.3.0-preview.1 → 0.3.0-preview.2 → 0.3.0` |

- Windows 保持 `desktop-app/package.json`、锁文件中的本项目版本及 `desktop-app/src/shared/contracts.ts` 的 `APP_VERSION` 一致。标签用 `desktop-v0.2.2`。
- Android 更新 `mobile-app/android/app/build.gradle` 的 `versionName`；每次对外发新 APK 时，`versionCode` 必须大于上一公开 APK，预览包也算。标签用 `android-v0.2.0` 或 `android-v0.2.0-preview.1`。
- 某个平台建立明确的核心功能、数据升级和兼容承诺之后，再单独定 `1.0.0`。另一平台可以继续保持 `0.x`。
- 在 GitHub Releases 上为已经验收的公开 `main` 提交创建标签，预览版标为预发布。发布说明列明本版变化、验证结果、已知限制；涉及升级时写出兼容和回退方式。已发标签不挪动，修复后发布新版本。

## 选取和核对

1. 写明源基线、公开目标和本轮核心场景。首发从选定的提交导出干净工作树，新建公开历史。以后在公开仓库的最新 `main` 上整理普通提交；不合并私有分支、不批量推送分支和标签，也不强推。
2. 只收录必要的源码、锁文件、构建与测试文件、有使用者的资产、许可证和公开文档。排除真实凭据和私有网关、本机账号或路径、任务和会话、账本、原始验收记录、安装包与缓存。自有代码遵循 [MIT](../LICENSE)，第三方保留各自声明。
3. 核对待发送的**每个提交**（也包括后来删除的内容）、最终树、文件体积、第三方授权和 Git 作者邮箱。优先用 GitHub 隐私邮箱。密钥筛查只报告位置；如果真实密钥已上过远端，先轮换，普通删除不会从历史中移除。
4. 从候选快照运行适用的验证。Windows 核心检查为 `npm run typecheck`、`npm run test:release`、`npm run build` 和 `npm run smoke`；Android 以[构建与验证](../mobile-app/README.md#构建与验证)为准。按改动范围补跑全量或对应功能回归；如实记录失败、环境限制和未验证项。预览功能不要求逐项实测。
5. 更新并复核公开远端，只推送待发布分支，例如 `git push origin refs/heads/main:refs/heads/main`；提交主题使用 `art:` 加简短中文说明。推送后用无登录访问确认公开仓库、默认分支、提交、README 和许可证可见。普通回退用新提交撤销，并更新说明。
