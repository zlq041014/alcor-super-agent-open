# 手机总管 R3 设计沿革

本文保留 2026-11-12 R3 方案中被星引继续采用的设计约束。当前开发范围、交互与放行条件以[手机总管首版设计](mobile-manager-v1.md)和[路线图](roadmap.md#mobile-manager-v1)为准。

<a id="r3-state-reliability"></a>

## 身份、事实归属与可靠执行

- **身份不随连接变化。** 设备有稳定身份，显示名可改，配对密钥可轮换。项目用稳定编号关联各设备的工作目录；项目同名或目录相同都不足以认定属于同一项目。原生会话按执行端、连接实例、环境或账号和原生会话 ID 区分。
- **按来源确定会话归属。** 用户手动更正或新建时明确选择的项目优先，其次尊重执行端自己记录的项目。只有缺少原生记录，且工作目录唯一匹配已登记项目时，才可按目录推断，并显示依据。不明归属保留为未归类。
- **任务、回合、请求各有身份。** 任务保存目标、约束、决定和验收条件；回合是一次执行尝试；请求有稳定编号、明确目标、授权范围和投递证据。跨执行端交接需要携带目标、证据、工作基线和原会话链接，不能假定原会话能迁移。
- **执行状态由执行端举证。** 手机和中继只保存或转发对应来源的副本。请求已到转发层不能证明电脑已接收，回合结束不能代替验收。失去回执时保留待核对状态；恢复时使用原请求编号找证据，不自动重发。
- **各端独立存储并按来源增量同步。** 同步保存来源序号、修订和缺口；不能用跨设备时间覆盖更新，也不直接同步仍在运行的 SQLite 文件。草稿可以在手机离线保存，审批、派工和控制权需要明确授权及回执。

<a id="r3-orchestrator-entry"></a>

## 总管入口与分期变化

R3 希望用一句话找回正确的项目讨论并接着聊。目标应显示项目、电脑和执行端；有歧义时让用户选择，保留不依赖模型的手动入口。会话名片是本地检索和离线阅读的线索，显示来源与更新时间，不能代替正文或执行证据。手机可直连模型完成独立对话，密钥存入系统密钥库；用户能查看本轮送给模型的上下文。

早期 R3 先汇报再输入，首期以找、续和汇报为主，派工后置。2026-11-24 的首版设计改成打开即对话，手机独立使用 DeepSeek，同时纳入经用户确认的单次电脑派工。首版以受控地找到原会话、发送到正确目标及同步真实状态为验收重点；多 Agent 持续推进不再作为开发主线。
