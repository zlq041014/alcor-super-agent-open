# 手机个人助手：随手记、接着聊、记得你，要动手时交给电脑

> 类型：产品定位、功能范围与实施设计
> 状态：2026-11-25 讨论结论与设计。M1 开发进度和验收结果见[路线图](roadmap.md#mobile-assistant-v2)；已交付的手机基线见[手机总管首版](mobile-manager-v1.md)
> 更新：2026-11-25（Asia/Shanghai）
> 适用：星引 Android、Windows Hub；模型先接 DeepSeek 官方 API，主要面向国内用户

本文记录 2026-11-25 的讨论结论，给出下一阶段的功能范围和实施设计。阶段划分与通过条件见[路线图](roadmap.md#mobile-assistant-v2)。

文中三类内容分开标注：

- **用户要求**：用户原话或明确确认的内容。
- **设计建议**：为落实要求提出的做法，开工前可由用户修改。需要用户拿主意的事集中在[待用户确认](#v2-open)。
- **现状**：以当前代码和已有验收记录为准。

<a id="v2-decisions"></a>

## 这次讨论定了什么

### 用户要求

| 方面 | 用户提出的内容 |
| --- | --- |
| 随手记 | 充当一个更智能的笔记本：路上突然想到的灵感，或别的要记的事，直接记一笔。 |
| 对话 | 「讨论」的分类过于明确。希望直接新开一个对话，在里面做调研、讨论、文案构思等。 |
| 助手能力 | 搜索、阅读网页链接、方案构思、设计文案、完成 PPT、架构图的讨论与预览。目标是一个能跑在手机上的满血 agent。 |
| 记忆与上下文 | 记住用户的喜好；长期管理和记忆；上下文自动压缩；对话风格与人格设定；本地数据库和手机本地缓存。 |
| 生活 | 查定位、看天气，下雨或极端天气时通知；查找附近外卖、美食、玩乐；整理相册；看时间；打开界面时给一句问候。 |
| 工作 | 总管管理各项目和子 Agent；预览并选择项目下的 Agent 结构；交互明确简单；已完成、待审核等事项点开查看后，通知或提醒自动消除；接入桌宠。 |
| 模式与权限 | 生活与工作模式切换并分开；权限设置。 |
| 模型 | Key 和模型由用户自己配置，不限于官方 DeepSeek，方向是适配各家模型的开源工具。**先做 DeepSeek，因为主要给国内用户用。** |

用户同时说明了自己的使用感受，作为取舍依据：豆包的模型不够强、推荐不够好，实际只当作更方便的搜索工具；cc-remote 更像远程遥控，给不了助手体验；DeepSeek 和豆包都开始对免费用户的复杂请求加额度限制。

### 已确认的决定

1. **定位扩大。** 手机端从「接着原来的事做」的工作总管，扩为生活和工作都能用的个人助手。工作总管是其中一部分。
2. **增加「记一笔」。** 手机同时是一个随手记录的笔记本。
3. **新开对话不必先分类。** 调研、讨论、文案构思都在普通对话里做。
4. **模型由用户配置，先做 DeepSeek。** 本阶段只接 DeepSeek 官方 API 并以它验收。适配其他模型和开源是后续方向，见[后续方向](#v2-later)。
5. **跨网络送达默认走更快的路线。** 直连优先，其次是用户自己的云主机中继，没有中继时才走第三方隧道。用户确认有一台本人所有的云主机可用作中继。做法见[跨网络送达](#v2-relay)。

### 没有改变的事

- 交给电脑的规则不变：用户在已选目标上明确发送才算授权，状态以执行端回执为准，结果回到原对话。见首版的[如何把话交回原项目](mobile-manager-v1.md#如何把话交回原项目)和[让等待可理解](mobile-manager-v1.md#让等待可理解)。
- 2026-11-24 确认的「手机入口简单」继续适用：首页仍是一个输入框，新能力以对话内的卡片和助手可调用的工具出现，不增加功能面板。
- 调用真实模型或执行端的验证需要用户的开工指令；公开发布和推送需要单独授权。

<a id="v2-positioning"></a>

## 定位、用户与差异

**一句话定位：** 一个用自己的额度、不受免费应用限额约束的私人助手。随手记、接着聊、记得你，要动手时交给电脑上的 agent。

**给谁用：**

- **入口用户：** 被免费应用的额度限制卡住、愿意按量付费的国内重度用户。
- **核心用户：** 自己电脑上跑着 Codex 或 DSH 的人。只有他们能用上「交给电脑」这一段。
- 只需要免费轻度聊天的用户，现有免费应用已经够用，不是本产品要争取的对象。

**差异在一条完整的链，而不在单个功能。** 一个想法从记下到做完要经过四步，现有产品各占其中一段：

| 环节 | 笔记应用 | 聊天应用 | 遥控应用 | 星引 |
| --- | --- | --- | --- | --- |
| 记下 | 有 | 部分 | 没有 | 本阶段新做 |
| 聊透 | 部分 | 有 | 没有 | 已有 |
| 交办给电脑 | 没有 | 没有 | 有 | 已有 |
| 结果收回原处 | 没有 | 没有 | 有 | 已有 |

补上「记下」之后，路上记的一句话可以一路变成项目里 agent 做完的结果，并能追溯到那句原话。

### 同类对照

以下来自 2026-11-25 查阅的公开文档和页面，没有安装实测。

| 类别 | 代表 | 电脑关机时 | 能进用户电脑上的项目 | 入口 | 数据位置 |
| --- | --- | --- | --- | --- | --- |
| 遥控类 | 官方 [Remote Control](https://code.claude.com/docs/zh-CN/remote-control)、[cc-remote](https://github.com/muggle-stack/cc-remote) | 不可用 | 能 | 会话列表 | 电脑 |
| 个人 agent | [OpenClaw](https://docs.openclaw.ai/zh-CN/platforms/android) | 不可用，手机是网关的配套节点 | 能 | 聊天渠道 | 网关电脑 |
| 消费级助手 | 豆包、[小豆](https://www.doubao.com/xiaodou/) | 可用 | 不能 | 聊天 | 厂商云端 |
| 星引 | — | 可用 | 能，电脑上线后 | 一个总管 | 手机 |

支撑取舍的事实：

- **免费额度在收紧。** DeepSeek 在 2026 年 11 月中旬开始限制 App 和网页版的免费用户：每日额度、单次输入约 4 万字、超过 7 天不活跃的长对话不能续聊；App 没有会员可买，API 不受这套限额影响（[第一财经](https://www.yicai.com/news/103441951.html)、[观点网](https://www.guandian.cn/article/20261120/630822.html)）。豆包的会员协议写明开通会员可解锁更多 AI 功能额度（[豆包付费服务协议](https://www.doubao.com/legal/ey01)）。
- **遥控类已经很成熟。** cc-remote 同时支持 Claude Code、Codex 和 DSH，能看完整过程、文件和终端。星引不在遥控深度上竞争。
- **生活服务是大厂的闭环。** 小豆有主动消息、每日简报、按位置推荐和打电话订位，并能连接抖音、日历和地理位置等应用。星引拿不到点评和下单能力，只做「找、比、推荐、跳转」。
- **多模型开源客户端已有成熟产品。** [RikkaHub](https://github.com/rikkahub/rikkahub) 是原生 Android 开源客户端（AGPL-3.0），支持多家接口、MCP 和让 AI 操作手机。多模型是入场条件，不是差异。
- **AI 笔记的通病是只进不出。** 得到大脑、flomo、ima 这类应用常被提到的问题是存得越来越多、回头看得越来越少（[第三方对比](https://www.linko.study/blog/how-to-choose-ai-knowledge-base-notes-app)）。星引的笔记不靠用户回顾，而是在相关对话里被带出来，或直接变成任务。

**据此的取舍：** 把力气放在「记下、聊透、交办、收回」这条链，以及记忆归用户自己、状态以回执为准这两点上。天气、附近推荐这类生活功能只做到够用，用来提高日常打开率，不作为卖点。

<a id="v2-goals"></a>

## 体验目标

1. **想到就能记。** 从主屏幕到记完一条只要几秒，不用想放在哪，没有网络也能记。
2. **想聊就开聊。** 新对话不用起标题、不用选分类。聊到要落到项目时再挂上去。
3. **助手自己动手。** 要查的自己去搜，贴了链接自己去读，知道今天几号、在哪座城市。
4. **聊得久，记得住。** 长对话不断片；用户说过的喜好下次还记得，而且看得见、改得了、删得掉。
5. **该提醒的提醒到，看过就不再打扰。** 提醒和通知点开即消除；待验收的事不因为看过就算完成。
6. **需要电脑时，仍由总管交接。** 沿用首版：发给谁、带什么、现在等谁，都看得见。

## 功能范围

编号里的 M1～M7 对应[路线图](roadmap.md#mobile-assistant-v2)的七个阶段。「现状」一栏为 2026-11-25 核对代码的结果。

| 编号 | 能力 | 用户能直接使用和测试的行为 | 现状 |
| --- | --- | --- | --- |
| M1.1 | 快速记一笔 | 从应用内入口、主屏幕图标长按、主屏幕小组件，或在别的应用里把文字、链接、图片分享给星引，都能记下一条。保存不需要网络，也不调用模型；强制重开后仍在。 | 已有：应用内输入框「记一笔」、快速记录页、图标快捷方式、一行小组件、系统分享文字/链接/图片；真机全项取证未完成。 |
| M1.2 | 收件箱与原文 | 新记录默认进收件箱，不要求标题、分类或项目。原文逐字保留，用户可以编辑；助手生成的标签、摘要和关联另存一层，可以清除。 | 已有：收件箱/已归入/已归档、原文、编辑、挂项目；标签和摘要未做。 |
| M1.3 | 找回 | 断网时按文字查找。联网时可以对助手说「上周记的登录页想法」，答复列出命中的笔记和记录时间；没找到就说没找到。 | 已有本机子串检索；对话内 `note_search` 属 M3，未做。 |
| M1.4 | 用起来 | 把一条或多条笔记转成新对话的材料、挂到项目、设成提醒，或在交接卡里作为所选材料。未经用户选择，笔记不会发给模型或电脑。 | 部分：转新对话材料、挂项目、设提醒和 Markdown 导出；多选和交接卡选材未做。 |
| M1.5 | 语音记一笔 | 按住说话，录音先存在手机；联网后转成文字，文字和录音并存。转写失败时录音仍在，可以重试。 | 未做。 |
| M2.1 | 新对话 | 点一下就开，不填标题、不选分类。首轮答复后自动有标题，可以改名。 | 客户端闭环已实现（抽屉直接开、改写不覆盖、无有效文字兜底）；官方服务端标题：首轮请求带 `title.enabled`，优先用返回标题，缺失时取首条用户消息前 24 字。浏览器假桥通过；真实请求返回了标题「只回复收到」，界面显示未在同一回合截图核对。 |
| M2.2 | 挂靠项目 | 任何对话可以之后挂到已同步的项目，挂上以后才出现「交给电脑」。原有项目讨论照常可用。 | 已实现：未挂项目的手机对话有「挂到项目」入口；挂靠页按电脑列出项目，写明只同步之后的消息；挂靠前不让发起交接，挂靠后关联页才出现「交给电脑」。浏览器假桥验证通过，真实电脑同步未验证。 |
| M2.3 | 本地数据库 | 升级后原有对话、决定、待发请求都在。笔记、记忆、提醒与对话存在同一个本地库里。 | 已迁移：`assistant.db` v4 的 `dialogs/messages/decisions/work/peers/projects/artifacts/meta`，旧 `discussions.json` 导入后保留逐字节备份且不再写入；真机迁移计数与隐藏旧文件后重启已取证。记忆、提醒与用量表未建。 |
| M2.4 | 长对话不断片 | 聊到几十上百轮，助手仍记得开头定下的事。内容多到需要压缩时，界面标出从哪里开始是摘要，原记录随时可看。 | 已实现（浏览器假桥）：取消最近 12 条上限，按字符预算并以上次接口用量校准；超预算自动把较早一段整理成前情摘要，保留最近一段和原文；摘要卡标范围和版本，可查看原文、带摘要开新对话；摘要失败时只带最近一段并提示；接口返回超长时压缩一次后重试。预算默认 8 万 token，设置页调整未做；已同步到电脑的对话只裁剪并提示，不在手机生成摘要。真实模型长对话未验证。 |
| M2.5 | 用量与花费 | 每轮可以看到用了多少 token、其中多少命中缓存，以及按公布单价估算的金额和当日累计。 | 已实现：SSE 最后一个内容块的 usage、命中/未命中/输出/思考 token、按 2026-11-25 单价估算本轮和当日金额；自定义网关没有 usage 时显示「接口未返回用量」。JVM 解析测试和浏览器假数据检查通过；真实官方请求返回 35 输入/14 输出、缓存 0/35，界面同一回合未截图核对。 |
| M3.1 | 自己判断要不要联网 | 不用说「搜索」。问到有时效的事，助手自己去查，答复附可打开的来源和检索时间；不需要联网的问题不查。 | 已实现客户端工具循环：官方模型收到 `web_search`，自行决定调用；来源和检索时间显示在可展开工具行。真实 DeepSeek 已验证一次工具调用和最终答复；自动决策、非时效问题不搜索和工具后下一轮未验证。 |
| M3.2 | 阅读链接 | 消息里贴上链接，助手就能读并引用其中内容；读不到时说明原因。 | 已实现 `web_fetch`：官方 Fetch 真实读取 5,929 字并交回模型；引用准确性和打不开时的逐项错误未验证。 |
| M3.3 | 知道时间和所在地 | 助手知道今天的日期和星期；经授权后知道所在城市。 | 已实现日期/星期：每轮用户消息前带 `latest_reminder`，北京时区，位置留空。浏览器格式检查通过；真实日期问答未取证，城市授权未做。 |
| M3.4 | 在对话里办小事 | 「记一下……」「明早 9 点提醒我……」「我之前记过什么关于……」直接生效。每一步做了什么在对话里看得到，写入可以撤销。 | 已实现笔记和一次性提醒的写入、确认与撤销；时间明确的提醒不调用模型，工具写入未跑真实模型。 |
| M3.5 | 权限页 | 一页列出助手能用的每项能力和每项系统权限：是否开启、用来做什么。关掉以后，助手明确说做不了。 | 已列出四项助手工具、当前系统权限和用户保留操作；关闭搜索或写笔记后的行为已用假桥验证 |
| M4.1 | 明确记忆 | 说「记住我不吃香菜」，记忆页出现一条带来源的记录，之后的新对话会用上；可以改、停用、删除。 | 已实现；隔离模拟器验证离线和重启，浏览器假桥核对请求。真实模型答复与备份恢复待验。 |

| M4.3 | 人格与风格 | 可以设定助手的名字、对用户的称呼、语气和详略。只改变说话方式，不改变回执、失败原因这些状态文案。 | 本地预览、保存与模型请求构造已验证；实际模型答复差异未验证 |

### 模型接入：先 DeepSeek 官方

**现状。** 手机只有一条 Chat Completions 通道（[Network.java](../mobile-app/android/app/src/main/java/app/alcor/mobile/Network.java)），请求体固定带 DeepSeek 写法的 `thinking` 和 `reasoning_effort`。可以填自定义网关地址和模型名；自定义网关用 Brave Search 搜索。

**本阶段的做法。**

- 完整能力以 DeepSeek 官方 Key 为基准验收。
- 自定义网关保留现有的对话和 Brave 搜索。工具调用、看图等能力取决于网关是否原样透传，逐项实测后在设置里显示「可用、不可用、未验证」，不默认可用。
- DeepSeek 专有的字段和接口集中在模型接入层。界面、存储和工具循环只依赖一份能力声明：流式、工具调用、看图、思考强度、用量回报、语音、文件解析。这是为后续接入其他模型留的唯一准备，本阶段不实现其他协议。

**官方接口的情况（2026-11-25 查阅官方文档）。**

| 事项 | 官方接口 | 对设计的影响 |
| --- | --- | --- |

<a id="v2-tools"></a>

### 工具循环与授权

助手的「自己动手」靠一个工具循环实现：模型提出调用，手机执行并把结果交回，直到模型给出答复。

**联网怎么接：客户端执行，对照后可换。**

官方有两条联网的路。服务端工具由 DeepSeek 在一次请求里完成搜索和读网页，调用不计费；Search、Fetch 接口由手机自己调用，按次计费。设计建议默认用后者，把搜索和读链接做成手机执行的函数工具，理由是：

- 官方文档把服务端工具定位为对话场景，写明 Agent 或自有程序应使用 Search、Fetch 接口。
- 助手同时要用本地工具（笔记、提醒、记忆）。服务端联网工具能否与函数工具在同一请求里声明，文档没有写明。
- 手机自己执行，检索结果和网页正文就留在手机上，来源可追溯、离线可读，这是首版已有的做法。
- 上层不依赖 DeepSeek 专有的内容块，以后接别家模型不用重写。

代价是每次搜索和抓取各约 0.005 元，并且用不上官方的多步深度搜索。M3 开工时先做一次对照：同一批真实问题分别走两条路，并实测服务端工具能否与函数工具共存。如果能共存且效果更好，只在接入层替换联网实现，上层不变。

**工具清单。**

| 工具 | 作用 | 类别 | 默认 | 需要的系统权限 |
| --- | --- | --- | --- | --- |
| `web_search` | 联网搜索，返回标题、链接和摘要 | 联网只读 | 开 | 无 |
| `web_fetch` | 读取用户给出或搜索得到的链接正文 | 联网只读 | 开 | 无 |
| `note_search` | 检索笔记 | 本地只读 | 开 | 无 |
| `note_add` | 记一笔 | 本地写入 | 开 | 无 |
| `reminder_set`、`reminder_list`、`reminder_cancel` | 设定、查看、取消提醒 | 本地写入 | 开 | 通知、定时 |
| `memory_search`、`memory_save` | 查记忆、存记忆 | 本地读写 | 开（M4 起） | 无 |
| `place_now` | 取当前的大致位置，用于「附近」类问题 | 设备只读 | 关，首次需要时询问 | 定位 |
| `weather` | 天气与预警 | 联网只读 | 数据源配置后开 | 无 |
| `calendar_read` | 读日程 | 设备只读 | 关 | 日历 |

今天的日期、星期和所在城市不走工具，每轮通过 `latest_reminder` 提供。

**规则。**

- **有界。** 每轮的工具调用次数和总时长有上限，超限即停并说明。起点值为每轮 8 次、总时长 90 秒，实测后调整。
- **可见。** 每次调用在对话里显示为可展开的一行：用了什么工具、参数摘要、结果摘要和耗时。失败显示原因，不编造结果。
- **资料是数据，不是指令。** 网页、文件、搜索结果和笔记里的文字不能驱动写入。实现上按「沾染」处理：本轮一旦读入了外部内容，之后的写入类调用不直接执行，改为在对话里给出待确认卡片，由用户点确认。
- **写入可撤销。** 记一笔、存记忆、设提醒成功后显示一条带「撤销」的提示。
- **直接记笔记。** 一轮最多记一条。用户明确说「记一下」并给出原文时，只能直接保存原文；涉及资料、历史摘录，或模型改写了原文时，展示拟保存的全文，由用户决定。撤销只作用于该次创建且未编辑、归档或挂项目的笔记。
- **删除不交给模型。** 删除笔记、记忆、照片只能由用户在界面上操作。
- **交给电脑不是工具。** 模型只能建议，仍走交接卡和用户授权，沿用首版规则。
- **模式决定可用工具。** 生活模式不提供项目相关的工具，工作模式默认不读生活笔记和生活记忆。

**思考内容要保存。** 官方要求带工具的请求回传历史中的思考内容。手机把每轮的思考内容作为协议记录保存：不进导出，不同步到电脑，界面默认不展示。它会计入上下文和费用。启用工具之前的旧对话没有这份记录，行为需要实测；兜底做法是把旧历史以摘要形式带入。

<a id="v2-notes"></a>

### 记一笔

**原则。**

1. **记的那一下不依赖任何东西。** 保存只写本地库，不发网络请求，不调用模型。整理、打标签、找关联都在之后。
2. **入口要比发给微信文件传输助手还快。** 快速记录用独立的轻量原生界面，直接写库，不等主界面加载。实测记录从点击入口到可输入、从保存到落盘的耗时。
3. **原话不改。** 助手永远不改写原文。标签、摘要、关联项目另存一层，可以整体清除。用户自己可以编辑，保留创建时间和最近修改时间。
4. **不要求分类。** 默认进收件箱。助手有把握才建议归属，没有把握就留在收件箱，不自动归档。
5. **笔记和记忆分开。** 笔记是用户写的，记忆是助手对用户的归纳。记忆可以引用笔记，不能改写笔记。

**一条笔记包含：** 原文；附件（图片、录音、链接）；记录时间和入口；所属模式；派生层（标签、摘要、转写文本、关联的对话或项目）；状态（收件箱、已归入、已归档）。

**笔记什么时候会离开手机。** 只有三种情况，且都由用户的动作触发：用户把它选进某场对话；用户让助手检索，命中的内容用于作答；用户点「整理」。自动整理默认关闭。「允许助手读取笔记」是权限页里的一项，按模式分开。

**找回。** 断网时用本地全文检索。联网时助手通过 `note_search` 查找，再由模型从命中结果里挑选和转述，答复列出所依据的笔记。系统自带数据库的全文检索能力和中文分词效果要在 Android 8 和真机上实测，不满足时退回子串匹配。

**M1 首个实现切片。** 先用 Android SQLite 保存笔记行，以不区分 ASCII 大小写的子串检索覆盖中文，不在数据库里内嵌大图。图片用应用私有的材料目录，完整落盘后才登记笔记；中途退出不会留下可见的半条记录。主屏幕快捷方式、小组件和系统分享都进原生记录页；给其他应用另留「记一笔」系统分享目标，原有的星引文件接收目标继续接收讨论材料。未进入 M4 前先以工作笔记为默认，挂项目只是本机标签。转入对话时，原文与图片作为可取消选择的本机材料；仅转入不会发送，交接的授权规则不变。

**用起来。** 一条笔记可以转成新对话的开场材料（对话里显示出处并可点回原笔记），可以挂到项目、设成提醒，或作为交接卡的所选材料。交接仍按首版规则带出处摘录，不整库上传。

**模式归属。** 新笔记沿用上一次记录时的模式，记录界面可以一键切换。这样既不要求分类，收件箱也不会成为两种模式之间的漏洞。

**语音。** 录音先以文件存在手机，记录立即成立。联网且用户允许时调用语音识别，转写文本进入派生层。单段不超过 120 秒，更长的录音分段转写。转写失败不影响录音。

<a id="v2-context"></a>

### 对话与上下文

**对话类型收敛。** 手机上只保留三种：首页的总管对话、普通对话（可选挂项目）、电脑上的原生会话（Codex、DSH，不变）。原来的「项目讨论」按已挂项目的对话显示，记录和与桌面共用的讨论 ID 不变。

**挂靠项目。** 没挂项目的对话只在手机上，不同步到任何电脑。挂到项目时界面写明「这段对话之后的消息会同步到这台电脑」。默认只同步挂靠之后的消息；挂靠之前的内容需要交给电脑时，由交接卡按用户所选的摘录带过去。

**标题。** 首轮请求开启官方的标题功能。没有返回标题时取用户首条消息的开头。用户改名之后不再被覆盖。

**找会话。** 保留按项目、最近、分类三种浏览。分类变为总管、对话、Codex、DSH。

**上下文怎么带。**

- **顺序。** 系统提示（含人格）和记忆摘要在最前，其后是历史，最后是 `latest_reminder`、本轮材料和本轮用户消息。稳定内容在前，才能持续命中缓存。
- **预算。** 取消「最近 12 条」的上限，在预算内带全部历史。预算的起点值为 8 万 token，可在设置里调整，实测后定。没有本地分词器，长度按字符估算，并用上一轮接口返回的用量校准。
- **压缩。** 历史超过预算时，把最早的一段整理成「前情摘要」。摘要保留已定的决定及其版本、用户明确要求的原话、未解决的问题和用过的材料清单；最近的若干轮保持原样。一次压掉较大的一段（压到预算的一半左右），避免每轮都压。
- **原文不动。** 摘要是派生记录，标明覆盖的消息范围和版本。原消息完整保留在本地。界面在压缩位置显示分隔，可查看摘要和原文。
- **失败时。** 摘要调用失败，本轮退回只带最近若干条，并在界面提示「较早的内容本轮没有带上」，不静默丢失，也不阻塞发送。接口因超长返回 400 时，触发一次压缩后重试。
- **用户可以主动处理。** 提供「压缩到这里」和「从这里开新对话并带上摘要」。

**取舍。** 官方上下文有 1M，缓存命中的输入很便宜，所以默认多带而不是早压。压缩会改写前缀，使之后一轮的缓存失效，过早压缩反而更贵。真正需要压缩的是超长对话，以及隔了很久再续聊、缓存已失效而用户又在意花费的情况。

<a id="v2-memory"></a>

### 记忆、人格与模式

**记忆条目包含：** 内容；范围（生活、工作、某个项目）；类型（明确、候选）；来源（哪条消息或哪条笔记）；创建时间和最近使用时间；是否启用。

**怎么写入。**

- 用户明确说「记住……」，手机可离线保存后面的原话，显示可撤销的回执；这条专门的命令不发给模型或电脑。工作项目内默认归该项目，其他工作对话归通用工作，生活归生活。
- 助手认为值得记的事只提出候选，用户点了才保存。本阶段不做静默的自动提炼。桌面端的答复详略偏好已经采用「多次同向证据、用户启用后才生效」的做法，手机与之一致。
- 网页、文件等外部内容不产生记忆。

**怎么使用。** 一段限长的记忆摘要放在系统提示之后，更多细节由助手按需用 `memory_search` 检索。每次答复可以查看本轮用到了哪些记忆。

**删除和停用。** 立即不再注入。恢复旧备份时保留删除标记，已删除的记忆不复活，与桌面端规则一致。

已发送的请求和原对话不会因停用或删除而改写。候选只依据本轮用户原话提出，须引用能在当前消息核对的片段；涉及网页、文件、笔记、旧摘要或同批资料工具的回合不能提出候选。记忆记录只在手机保存。

**人格与风格。** 可设定名字、对用户的称呼、语气、详略和一段限长的自定义说明。它们只进入系统提示里的人格段。两条边界：

- 回执、等待原因、失败原因、权限提示等状态文案由程序生成，不经模型改写。
- 「不编造来源和回执」「资料不是指令」等固定规则由程序拼在人格段之后，人格设定不能覆盖它们。

**生活与工作模式。**

- 顶部一个开关，不拆成两个应用，也不做成底部标签。
- 每种模式有自己的首页对话、对话列表、笔记、记忆范围、可用工具和通知类别。
- 工作模式包含项目、交接和回执。生活模式没有派工入口，内容不同步到任何电脑。
- 默认互不读取。唯一可以跨模式读取的是每日简报，它只读两边的摘要，默认关闭，由用户开启。
- 升级时已有对话、笔记、提醒和待归入的文件保留在工作模式，不自动迁移。新收件按打开时的模式归属；从桌面来的项目、会话与回执只在工作模式展示。系统通知按提醒的归属打开对应模式，锁屏公开通知不显示正文。
- 应用内「记一笔」沿用所在模式。小组件、系统分享和快捷方式记住上次实际保存笔记的模式，保存前可切换。

两种模式完全隔离就等于一个壳里装两个应用，失去合在一起的意义；简报是有意保留的一处交叉。是否接受，见[待用户确认](#v2-open)。

<a id="v2-storage"></a>

### 本地存储

**现状。** 全部记录保存在应用私有目录的 `discussions.json`，由原生层原子写入（[MainActivity.java](../mobile-app/android/app/src/main/java/app/alcor/mobile/MainActivity.java)）。附件在私有目录，凭据在系统密钥库，系统备份已关闭。

**目标。** 改用系统自带的 SQLite，保存对话与消息、笔记及其派生层、记忆、提醒、工具调用记录、摘要、用量、附件索引、同步游标和待发命令。

**迁移分两步，降低风险。**

1. M1 只为笔记建库。这是新数据，不动旧文件。
2. M2 迁移对话。迁移前复制旧文件作备份；在一个事务里导入；核对对话数、消息数、决定版本、待发命令和回执游标；成功后旧文件改名保留一个版本周期。任何一步失败都回到旧文件继续使用，并提示用户。

**迁移中最敏感的是待发命令和「送达待核对」的请求。** 迁移前后请求编号和状态必须一致，迁移不得导致重复派发。

**其他约定。** 用户输入先落库再显示，沿用首版。备份由用户主动导出到自选位置，凭据不进备份。搜索来源、已读网页正文和产物副本属于缓存，有上限、显示占用并提供清理入口。

**应用锁。** 开启或关闭均需通过系统验证；开启后冷启动、离开应用后返回和从小组件、快捷方式或通知进入都先解锁。支持系统强生物识别的设备使用指纹等生物识别，也可以用锁屏密码；旧系统用锁屏密码。认证在 Android 原生层完成，锁定时遮住界面并拦截读取、导出和复制。系统提醒仍按原计划发送。

**备份恢复边界。** 通过系统文件选择器导出、预览和恢复；文件只收录明确支持的业务数据与附件，不打包应用目录或凭据。恢复按稳定编号合并，不覆盖已有记录，也不恢复桌面配对、派工授权或执行队列。先合并已知删除标记，再插入有效记忆；当前数据和所选备份都没有删除标记时，系统无法推断曾删除过该记忆。

首版备份包含双方模式的对话正文和草稿、笔记、记忆、提醒及被直接引用的附件。同步对话恢复为本机副本；旧任务、对话中的工具状态和缓存不导入。已过期提醒只留历史。备份文件未加密，选择保存位置前告知用户；恢复前显示文件内的各类记录数。

<a id="v2-life"></a>

### 生活能力

- **定位。** 只在前台取粗略位置，不申请后台定位。用户拒绝时可以手填城市。国内机型没有 Google 服务，定位和地名解析不能依赖它，需在真机上实测。
- **天气。** 需要一个结构化的天气与预警数据源，要求支持按经纬度或城市查询，并提供降水预报和官方预警。项目目前没有接入任何天气服务，按约定不预设账户，选型和 Key 由用户决定。选定之前，「今天天气怎么样」可以由联网搜索回答，但不能支撑定时预警。
- **问候。** 显示在首页顶部的一行，不占对话、不挡输入。默认由程序用本地时间和已缓存的天气拼出，不为问候单独调用模型，这样不花钱，也不拖慢启动。可以在人格设置里改为由助手撰写，每天最多调用一次。
- **雨天与预警通知。** 由系统的周期任务定时检查，间隔下限为 15 分钟，实际时机由系统决定。用上次已知的城市；命中规则才通知；同一事件不重复；支持安静时段。应用被系统清理后可能不触发，界面如实写「尽量送达」，并引导用户在系统设置里允许后台运行。
- **提醒。** 用户设定的提醒走系统的定时闹钟，比天气检查可靠。它需要通知权限；新系统上的精确定时还需要用户许可，被拒绝时降级为非精确并在界面说明。
  - 首版是一条一次性提醒：列表分「待提醒／已过」，支持手动新建、从笔记带入、修改和取消。显示手机本地时间，通知点开对应记录；锁屏隐藏提醒正文。应用划出最近任务后由 Android 继续调度，系统强行停止和厂商限制会影响送达。
  - 「明早 9 点提醒我带伞」「3 分钟后提醒我喝水」这类时间和原文明确的输入在手机离线完成；模型推断出来的时间或内容只展示待确认卡。未开启通知时仍可保存，但不显示为已经通知。
- **附近的吃和玩。** 输出候选、理由、依据来源和跳转链接，结合记忆里的口味。数据先来自联网搜索，接入地图的地点检索服务后会更准，该服务同样待选型。不代下单，不代订位。
- **相册整理。** 用户用系统照片选择器圈选一批，不申请全库读取权限。助手看图后给出整理建议，用户确认才执行，删除走系统确认。看图会把照片发给模型，发送前显示张数和预估费用。不做全库后台扫描。

<a id="v2-notify"></a>

### 通知、未读与后台边界

**通知类别：** 提醒、天气预警、工作事项（待答问题、待验收、失败、完成）。每类可以单独关闭。工作通知的正文只写事件类型、电脑名和项目名，不带对话标题和正文。

**已读和已验收是两件事。**

- 每个事项有未读标记。打开对应详情，未读和系统通知一起消除。
- 消除未读不改变事项状态。待验收的结果在用户验收或检查通过之前，仍留在待处理里。这与首版「待验收到已完成」的规则一致。
- 已完成的结果看过之后不再提示，记录保留。
- 手机在同一次本地保存中记录回执游标和未读，再向 Android 申请系统通知。同一请求的同一问题或回合状态不因回执补全、重放或重开而再次提醒；通知权限关闭时仍保留应用内未读。点通知打开工作侧对应详情，不自动验收或回复。
- 一项工作只保留当前未读提醒；同一批同步里已经被新状态替代的提醒不再弹出。关闭通知期间收下的未读不会在重新开启时补弹。

**能通知到什么程度。**

- 工作通知只在手机连着 Hub 并收到回执事件时产生。首版只有局域网直连，离开局域网收不到，跨网络见下一节。
- 国内厂商的推送通道需要企业开发者账号（项目 2026-11-11 调研），因此不依赖厂商推送。
- 应用被系统清理后不保证送达。提醒是例外，它由系统定时触发。

<a id="v2-work"></a>

### 工作总管补全

**Agent 结构预览。**

- 手机协议现有 `catalog`、`history`、`pull`、`push`、`command`、`artifact` 六种操作。新增一项只读查询，只返回已共享项目内的 Agent。
- 每个节点返回稳定的 Agent 编号、父节点、执行端、模型、账本里的当前状态、最近活动时间，以及关联的工作或会话。不返回正文。
- 手机上用可折叠的层级列表呈现，窄屏上比连线图好读。点节点进入对应的会话记录或工作回执。「选择」的含义是把该 Agent 所在的会话作为交接目标，仍然走交接卡。
- 状态只来自账本，不推断。离线时显示缓存和同步时间。撤销共享后不再可见。
- 没有可核实的原会话绑定时不提供设为目标，仍可查看存在的上级讨论或本手机的回执。只投影当前项目最近 250 个节点；父节点不在共享项目或窗口内时平铺，不暴露别的项目。旧桌面暂不提供结构时显示读取失败，不影响已有会话和交接。

**跨网络送达。** 经用户自己的云主机转发，做法见[下一节](#v2-relay)。

**小引。** 应用内复用同一套精灵表和[动作与回执的对应表](desktop-pet.md#动作与触发证据)，位置在首页头像处。手机新增的触发（例如「记下了」）先改 `desktop-pet.md` 再重新生成素材。不做系统级悬浮窗。

<a id="v2-relay"></a>

### 跨网络送达：路线选择与自有中继

**资源。** 2026-11-25 用户确认有一台本人所有的国内云主机可用。旧项目用它做过转发，实测经它访问办公网服务的往返延迟为 20–26 ms。它的固定带宽为 3 Mbps，与主机上已有的其他用途共用。本文不记录主机地址、账户和端口。目前还没有为星引连接或改动过这台主机。

**原则：云主机只搬运密文。**

- 加密仍在手机和 Hub 之间完成。手机连接电脑时只认配对时记下的证书指纹，不看主机名（[Network.java](../mobile-app/android/app/src/main/java/app/alcor/mobile/Network.java)），所以经云主机透传之后，身份校验不变。
- 云主机不运行总管，不保存请求、回执或待办。电脑不在线时，请求留在手机上待发，规则与首版相同。
- 电脑不开放入站端口，由电脑主动连到云主机。

**连接路线：默认用更快的。**

每台电脑可以有多条到达它的路线。手机自动选用，不需要用户切换。

| 优先级 | 路线 | 什么时候用 |
| --- | --- | --- |
| 1 | 直连：局域网地址，或其他能直接到达电脑的地址 | 可达就用 |
| 2 | 自有中继：用户自己的云主机 | 直连不可达时 |
| 3 | 第三方隧道：用户自己安装的组网或隧道工具给出的地址 | 没有配置中继，或中继不通时 |

- **高一档可用就不用低一档。** 排序依据是实测：旧项目在同一环境下，经自有云主机为 20–26 ms，经第三方隧道为 300–800 ms。
- **怎么选。** 网络变化和应用回到前台时，同时探测所有已配置的路线，取通过证书校验的最高一档。停在低档期间定期重试高档，可用就切回去，例如回到家连上 Wi-Fi 后自动回到直连。选路在后台维护，不在每个请求里逐条尝试，免得每个请求都先等一次超时。
- **切换不会重复执行。** 所有路线到达的是同一个 Hub，用同一个证书指纹和设备令牌。请求带稳定编号，换路线重发时 Hub 按编号去重；发出后没有回执的请求仍按首版规则进入「送达待核对」。
- **第三方隧道的边界。** 星引不内置、不绑定任何一家隧道工具。由用户自己安装，再把它给出的地址填进来。只支持不在中途终止加密的方式，即组网类或 TCP 透传。会在中途终止 TLS 的隧道，证书指纹对不上，连接会被拒绝，这是有意保留的保护。
- **配对只在局域网入口进行。** 中继和隧道入口都不接受配对。

**自有中继分两步做。**

1. **先用 SSH 反向隧道验证。** 电脑用系统自带的 OpenSSH 连到云主机，把云主机上的一个专用端口转到本机的手机入口。云主机上不需要装新程序，旧项目已经用这种方式跑通过。
2. **对外提供时再换成纯转发中继。** 按旧项目 R3-C1 方案的方向：中继先核对设备公钥，再对接两条连接，未登记的设备到不了 Hub；手机和 Hub 改用双向 TLS，设备令牌不再经公网传输。只有用户本人使用时不需要这一步。

**第一步要做的改动。**

| 位置 | 改动 |
| --- | --- |
| 手机 | 每台电脑可以存多条路线：局域网地址、中继地址和用户填写的隧道地址，按上面的优先级自动选路。中继和隧道地址可以来自配对码、电脑经已校验的连接下发，或用户在手机上手填；无论哪种来源，连接时都校验同一个证书指纹。界面显示当前走的是哪条路线。 |
| Hub | 为中继和 TCP 透传类隧道单开一个只监听回环地址的入口；组网类工具给出的地址作为额外的监听地址加入。这些入口都不接受配对，新手机只能在局域网配对。在设置里填写中继地址；启动并看管到云主机的隧道进程，断开后退避重连，状态显示在「手机接入」里。隧道密钥留在用户目录，Hub 只保存路径。对未通过鉴权的连接设并发上限和握手超时。 |
| 云主机 | 一个只能做端口转发的专用账户和密钥，限定只能监听那一个端口；安全组只放行该端口。不改动主机上已有的服务和端口。 |

**连接复用。** 按现有写法，手机每次请求都新建连接并重新握手。经中继或隧道时，这会让每个请求多付几次往返。跨网络这一步同时改为按电脑复用连接，效果以实测为准。
**带宽。** 旧项目出过一次大流量挤占 3 Mbps 出口、导致其他服务卡顿的事故。因此经中继默认只传文字，包括消息、回执和摘录。附件原件等回到局域网再传；用户也可以逐次确认后经中继传，传输限速。

**它解决不了的事。** 中继只在应用运行时把回执带回来。应用被系统清理之后的通知仍然收不到。

**部署约定。** 连接和改动云主机需要用户的明确指令和凭据。每次改动记录做了什么、怎么撤回。

<a id="v2-output"></a>

### 成果

- **架构图。** 助手输出 Mermaid 代码块，手机本地渲染成图，可以缩放、导出图片或复制源码。渲染库随包内置，接入前核对许可证和体积。渲染失败时显示源码和错误。
  - 使用无 HTML 标签的 Mermaid 流程图、时序图、类图或状态图。只处理已结束答复或回执里的 Mermaid 代码块；不执行图内动作或加载外部图片。放大和缩小只影响预览，PNG 导出整张图。
- **PPT。** 先交付逐页大纲与要点、按页预览和 Markdown 导出。生成 `.pptx` 有两条路：手机端用库生成，离线可用但样式有限；交给电脑执行端，样式更好但需要电脑在线。选哪条见[待用户确认](#v2-open)。
  - 大纲来自已完成答复或回执的 `alcor-slides` JSON 代码块，字段是总标题、按序排列的页（标题、要点、可选讲稿）。同一份经校验的数据用于逐页预览和 Markdown 导出；坏大纲保留源码和错误，不猜测页序。
- **文案。** 沿用首版的候选文案卡片。

<a id="v2-ui"></a>

### 界面：原型与界面设计建议

2026-11-25 按本文的范围做了一份[网页设计原型](../mobile-app/prototype-v2/README.md)，覆盖首版已交付的界面和 M1～M7 的全部界面，含小引。它只用来对齐交互和视觉：页面不连接模型、Hub 或执行端，内容都是示例，回执由页面模拟。它不是实现，也不是验收证据。

实现按这份原型还原，按阶段先做本阶段屏幕；首个可用版本先对齐首页、抽屉、快速记一笔和收件箱。视觉和交互有冲突时以原型为准，功能边界以本文为准。

原型里有几处本文其他小节没有写到的做法，记在这里。它们都是设计建议，用户可以改；改了先改本节。

| 方面 | 原型的做法 | 依据或取舍 |
| --- | --- | --- |

## 约束与取舍

| 约束 | 影响 | 取舍 |
| --- | --- | --- |
| 官方接口无状态，不提供上下文压缩，超限返回 400 | 长对话管理全在手机端 | 预算内带全量，超出才压缩，原文保留 |
| 带工具的请求必须回传历史思考内容 | 思考内容要落库，并占用上下文 | 保存但不展示、不导出、不同步 |
| 服务端联网工具面向对话场景，与函数工具能否共存没有写明 | 不能假设搜索和本地工具可以同请求使用 | 默认由手机执行搜索和抓取，对照实测后可换 |
| Android 限制后台运行，厂商推送需要企业账号 | 预警和工作通知不保证送达 | 定时检查、尽量送达；提醒走系统定时 |
| 首版只有局域网直连 | 出门后收不到电脑回执 | 直连优先，其次自有云主机中继，没有中继时才走第三方隧道 |
| 云主机固定带宽 3 Mbps，且与其他用途共用 | 大流量会挤占主机上的其他服务 | 经中继默认只传文字，附件原件回到局域网再传 |
| 拿不到点评、下单类数据和接口（未逐家核实） | 推荐数据有限，不能下单 | 只做找、比、推荐、跳转 |
| 看图、读文件、检索笔记都会把内容发给模型服务 | 涉及隐私和费用 | 发送前可见，按模式和开关授权 |
| 由一个人维护 | 功能面不能铺太开 | 每阶段一个可验证的闭环，通用 agent 能力不拼广度 |

<a id="v2-later"></a>

## 后续方向：多模型与开源

用户的方向是做一个适配各家模型的开源工具。本阶段不实施。这里记录讨论中的判断和已核实的事实，供届时使用。

**多模型。**

- 三种协议可以覆盖绝大多数供应商：Chat Completions、Responses、Anthropic Messages。DeepSeek 官方三种都支持。
- 每个接入声明自己的能力，缺哪项就明确说做不了，与执行端分别声明能力的做法一致。
- GPT 和 Claude 的官方接口在大陆通常不能直连（未实测），每个接入都要能填自定义地址。
- 工具由应用自己执行，这一点本阶段已经按此设计。

**订阅不等于 Key。**

- Claude 的订阅登录只供 Anthropic 自家应用使用，官方不允许第三方应用提供 Claude 账号登录或经手订阅凭据，第三方要用 API Key（[Anthropic 帮助中心](https://support.claude.com/zh-CN/articles/13189465-%E7%99%BB%E5%BD%95%E6%82%A8%E7%9A%84-claude-%E8%B4%A6%E6%88%B7)）。
- ChatGPT 的订阅不提供 Key。OpenAI 有官方的「使用 ChatGPT 登录」，订阅用户可以在已接入的应用里消耗套餐额度（[OpenAI 帮助中心](https://help.openai.com/zh-hans-cn/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)）。接入条件没有核实。
- 星引已有一条用上订阅的路：用户的 Codex 如果用 ChatGPT 套餐登录，星引把任务交给它，额度由官方客户端消耗。

**开源的前置项。**

- 仓库根目录没有许可证文件。远端匿名访问返回 404，目前不是公开仓库。
- 许可证要早定。借用 RikkaHub 的代码就必须采用 AGPL；不借用可以选 MIT 或 Apache-2.0。
- 公开前清理文档里的个人环境信息：`mobile-app/README.md` 的示例里有私有网关域名，多份文档里有本机路径和设备型号。
- 发布和推送需要用户单独授权。

<a id="v2-unverified"></a>

## 未核实与待实测

**同类产品。**

- 所有同类产品都没有安装实测，结论来自公开文档和页面。
- 豆包按功能限次的具体数字来自第三方整理，没有在账号页面核对。
- 「美团、饿了么没有面向个人应用的下单接口」是未逐家核实的判断，接入前需要再查。
- 用户认为豆包模型不够强、推荐不够好，这是一个使用样本。星引的推荐是否更好没有证据，路线图里安排了同题对照。

**官方接口。**

- 服务端联网工具能否与函数工具在同一请求里声明。
- 启用工具之前的旧对话没有保存思考内容，带工具继续时接口的行为。
- 自定义网关是否透传工具调用、看图和用量字段。
- 语音识别在嘈杂环境和口语下的质量。

**跨网络。**

- 没有为星引连接过这台云主机，它当前的系统、SSH 配置和安全组没有核对。
- 手机在蜂窝网络下到云主机的延迟和稳定性。
- 与主机上已有用途并行时的带宽占用。
- 第三方隧道没有在星引上测过。上文的延迟数字来自旧项目的另一条链路。
- 手机复用连接之后，经中继的实际请求耗时。
**手机系统。**

- 在 V2338A 上，周期任务在应用进入后台和被清理后的实际触发情况。
- 精确定时权限在 Android 16 上的授予流程，以及被拒绝后的表现。
- 没有 Google 服务时的定位和地名解析。
- 系统自带 SQLite 的全文检索能力和中文检索效果。
- 主屏幕小组件和图标快捷方式在国内机型上的可用性。
