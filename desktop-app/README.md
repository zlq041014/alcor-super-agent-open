# 星引 Alcor 桌面端

0.2.1 已切换为本机日用版。「设置 → 手机接入」可按项目生成一次性配对码，并撤销已有手机授权。配对和选择原会话见[手机端 App 开发](../mobile-app/README.md)，切换与回退证据见[手机联调记录](../docs/roadmap.md#mobile-manager-v1)。

> 类型：开发与使用说明  
> 状态：有效；可运行首版候选，正式 D2 放行与本人试用分别记录  
> 更新：2026-11-23（Asia/Shanghai）  
> 适用：Windows x64，DeepSeek Harness 0.2.2-rc.5 或 Codex CLI 0.169.0-alpha.11.1 / 0.169.1

星引默认打开同一条跨项目总管对话。需要深聊或指导执行时，点右侧 Agent 树的名字，中间会切换到该 Agent；点「回到总管」返回原处。项目、讨论、委派关系、执行和结果保存在本机 SQLite。

**0.1.8 模型与执行端：** 总管、讨论、执行及下级 Agent 默认使用自定义 API 的 `deepseek-flash`，思考强度为 `max`。新工作默认交给本机 DSH，也可在设置里选择 Codex。已创建的工作保留原执行端。升级会更新旧内置默认值；自选模型及历史运行快照保留。

**0.1.7 本机项目：** 打开「项目 → 添加查找位置」，一次选择一个常用父目录，例如 `D:\projects`。启动、手动刷新和总管找项目时会检查直属文件夹，不需要 Git 或 Codex 登记。更深层的仓库可添加其直接父目录，或点「选择已有文件夹」。同一路径只显示一次；有 Codex 记录时关联到原项目。

在总管说「找一下天气记录项目」或「看看天气记录项目的进度」。同名时点完整路径；未命中会说明查找范围，可选已有文件夹或新建，之后继续原请求。明确说「在 D:\projects 新建项目『天气记录』」可以直接创建空文件夹；已存在则可选择复用。也可在项目页点「新建项目」。尚未设置查找位置时只使用已知绑定与原生目录，不会自动遍历磁盘。

本机可选装 voidtools 官方 **Everything 1.4.1.1032 x64 便携版**（[官方下载](https://www.voidtools.com/downloads/)），置于 `D:\apps\portable\everything\Everything.exe`。识别到已验证版本后，项目页显示「在 Everything 中浏览」：可按文件夹名或路径筛选并打开项目。每次点击都用实际目录刷新清单；范围为已选位置内的项目及手动绑定的文件夹。清单与独立实例的配置在星引数据目录的 `everything` 下。该入口不安装服务、不需要全盘索引，也不包含项目里的文件或正文。Everything 未安装时，星引的查找、新建、资源管理器入口仍可用。

**0.1.5 聊天：** 点击发送或按 Enter 后，你的消息立即显示在右侧，输入框清空，可以直接写下一条。总管、讨论和执行 Agent 的回复、系统提示与工作记录均在左侧。收到回执后原地更新同一条消息；明确失败可放回空输入框，送达未知不会自动重发。切换 Agent 不会把旧回复或正在输入的草稿带到其他对话。

新建节点时可接受默认值，或读取当前提供方的模型目录再选。取消不会建节点或启动任务。点节点输入框旁的模型按钮可单独修改，下一轮生效；设置页可改总管和未来新节点的默认值。

选择 **Codex** 时，托管工具审批默认 `never`（不逐次询问）；创建工作时可选沿用本机 Codex 有效权限、只读或仅项目内修改，也可选择独立工作区。设置中的 Codex 选项可以改回按需询问。**DSH** 则始终使用本次工作选择的文件范围，例外授权不会自动放行。

**0.1.3 工作记录：** 总管、讨论和执行 Agent 的对话正文里都有可展开的「工作记录」。点开后，按发生顺序查看项目资料读取、模型调用、委派、命令、图像和文件修改；再点一条命令看输出及退出码，点文件名看已记录的补丁和增删行数。执行者公开的阶段说明穿插在操作组之间。公开摘要、计划和阶段核对结果可以展开；供方没有提供的思考内容不会生成替代文本。只有版本变动而没有行级补丁，会明确注明。旧会话只能展示当时留存的证据。

**0.1.2 试用路径：** 在总管说「为〈项目名〉新开『桌面交互』需求讨论」（也可用右下角「新建项目讨论」）。在讨论里先谈需求，不派发执行；说「按刚才讨论的方案做，某项暂缓」后，总管整理目标、约束和验收条件，委派 Codex 执行 Agent。可以回总管处理另一个项目。需要审批、执行受阻、回合结束时，总管会收到带入口的消息；执行结果也会回到原讨论。说「继续昨天〈项目名〉的桌面交互讨论」可接着聊，多个候选时会列出选项。

执行 Agent 的「对话与过程」按顺序显示用户补充、执行回复、工具和上游提供的公开思路摘要；没有摘要就不生成替代内容。运行时 Enter 补充当前轮次，也可勾选「排到下一轮」；消息显示排队、接收、失败或未知。已结束的工作可在原范围内续聊。原有暂停、停止、修改要求、核对、验收和产物操作在主页面的「工作详情与操作」。每项工作仍有运行次数限制；未知回执不自动重发。

树上的根是总管，下面是实际委派的讨论 Agent、托管执行 Agent；重试不会伪造新节点。讨论可交接给执行者，也可在执行节点明确委派一个只读核对成员，同一工作区仍遵守原有串行调度。原生 Codex 会话不会被自动挂成下属；可在原生记录里选择引用历史到新的星引讨论，或在原 owner 在线时使用原有续聊入口。

0.1.1 修复了“已有项目找不到”：启动时自动读取 Codex 已登记的本地项目，项目页支持手动刷新。聊天中询问项目进度或补充项目名称，会在同一轮读取所选项目的入口文档、近期原生会话和 Git 状态，再给出带来源/时间的答复。目录索引不是写入授权，查进度不会创建执行任务，也不会发送消息到原生会话。

在项目讨论写好本次要求，点「准备派工」可核对目标、约束、验收条件及实际带上的讨论摘录。草稿保留；只有确认才创建一项单次工作。讨论或规则变了，需要重新准备。可用隔离测试验证准备、取消、确认和重启，不需要正式模型。

「Agent 名册」可登记托管成员和只记录分工的成员。一个身份可关联多个项目；只有可用执行端上的托管成员才能准备派工，确认后才新建单次工作。手机只看获准项目的承办信息。

「留用架」可以把已验收的一段文字按版本交给明确允许的项目。新任务由用户确认，复用不会共享原目录或文件。核对交付后可登记实际采用，也可记录反例并停用。

「已处理」显示最近的人工验收记录。可以核对当时对应的回合和版本；旧证据不可核对时保留记录，不显示新版来替代。

设置可分别读取 Codex 与托管 DSH 的可选执行模型，并将核实的来源及模型设为新工作默认。托管 DSH 使用已配置的 API 候选，经 ACP 会话确认，目录检测不发送模型任务。总管对话仍使用单独的 API 设置。

## 直接运行

只想试用时，运行解压目录中的 `启动独立试用.cmd`，并打开 `试用样例/试用步骤.md`。独立入口固定使用包旁的 `trial-data` 和隔离的 Codex 数据目录，不打开日常账本。

解压 Windows x64 便携 ZIP，双击 `Alcor.exe` 或 `启动星引.cmd`。整个目录须一起保留；无需安装 Node.js 或 npm。便携包未签名，不包含账户、密钥、真实任务历史、DSH、Codex 或 Everything 本体。日用版为 0.2.1，保留已有推进循环。

Windows 打包会把新生成的便携目录及其文件标为正常的中完整性，避免输出目录带有低完整性时导致 Electron 启动即退出。ZIP 不携带 NTFS 完整性标签；解压时请使用普通目录。修复只涉及已核对的项目或程序目录，无需管理员身份，也无需关闭沙箱。

默认数据目录：`D:\data\alcor\desktop\default`。设置中的“选择数据目录”作用于下次启动，不迁移旧数据。可先备份，在新目录启动后恢复。目录选择记录位于 `D:\data\alcor\desktop\location.json`；窗口缓存位于当前数据目录的 `shell/`。D 盘不可用时不会静默转存 C 盘。

## 首次配置

1. **自定义 API（默认）**：“设置 → 总管模型 → API 来源”保留“自定义 API”。填入你自己的兼容 HTTPS 端点；未配置时请改用 DeepSeek 官方模式。点“自定义 API 密钥设置”，录入对 `deepseek-flash` 有权限的 Key。网关的 GPT 专用 Key 可能会返回 403。
2. **DeepSeek 官方（可选）**：在同一处选择“DeepSeek 官方 Key”，点“录入 DeepSeek 官方 Key”。官方模式锁定 `https://api.deepseek.com` 与 Chat Completions。两种 Key 分开用 Windows DPAPI 保存；切回自定义 API 会恢复原地址、协议和凭据。普通页面、备份及诊断都不会得到 Key。
3. 点“测试连接”核对服务实际返回的模型；失败不会自动换端点、模型或强度。继续已有节点时，如果该节点曾自选只在旧提供方可用的模型，请单独修改节点。
4. **托管执行端**：默认 DSH，自动查找本机 DeepSeek Harness，未找到时填写 `DeepSeek Harness.exe` 的完整路径。“检测 DSH 连接”核对 ACP、模型和强度，不发送任务、不消耗模型额度。DSH 的模型请求使用上面选定的提供方。若选择 Codex，则配置原有 `codex.exe` 和原生登录／独立提供商凭据；Codex 能用哪些模型取决于其自身配置。

DSH 可以读取项目文本、列目录、创建或修改 UTF-8 文件；只读任务没有写工具，超出所选目录、链接、受保护文件和覆盖同名新文件均拒绝。修改已有文件需要精确匹配原文。执行中补充会排到下一轮；需要终端命令或图片附件可选 Codex。DSH 原桌面已有会话不会自动导入或接管。密钥换用户或换电脑后需要重新填写。

## 日常使用

- **管理项目**：每个查找位置最多检查 1000 个直属目录项（最多 12 个位置），跳过目录链接、点开头的目录和常见依赖/产物。超出范围或无法访问时有提示。停止查找保留已登记项目；移除项目只隐藏索引，后续发现不会重新添加。项目改显示名称不改磁盘文件夹；暂时失联的项目保留任务和历史。
- **查看文件夹和查找文件**：在总管聊天输入 `看看 D:\projects 里有什么`，可直接列出直属项。在已选查找位置按名称搜索可输入 `查找文件 manifest.js`，也可用 `在 D:\projects 查找文件夹 tech-art` 指定位置。查找使用随包的 [fd](https://github.com/sharkdp/fd)，跳过隐藏项、目录链接和常见依赖目录。两种操作都不读正文，不依赖 Codex 或模型，最多显示 30 条。
- **查看进度**：直接说“看看某项目开发到哪一步了”，或在项目卡点“查看项目进度”。只读取当前项目中固定的 README/进度入口、Git 摘要，以及最近最多 4 个匹配会话的各 3 个回合；不扫描全盘，不改项目文件，不续接原生会话。来源可展开，原生记录可点击核对。部分历史、离线与文档截断会明确标注。
- **聊天与工作**：普通对话由总管回答。创建工作时选择项目、执行范围、模型、强度、约束和交付依据。确认后才启动；运行中的任务契约变更会使旧版本失效，单独修改模型不打断本轮。
- **结果核对**：工作详情包含执行者原始回复、原生差异、实际命令/退出码、用量和文件版本副本。执行完成进入“待验收”；确认对应版本后进入“已完成”。也可预先声明文件/文本检查足以判定完成，程序核对后自动收口；失败时最多修正两次且不增加总尝试额度。已完成任务可继续修改并沿用任务身份。
- **暂停与继续**：暂停立即阻止后续派发；原生停止未确认时显示“停止待确认”。未知结果保留工作区占用，先“核对原生状态”，不会自动新建执行重复操作。已暂停任务不会因重启自动恢复。
- **原生会话**：按授权目录查看最近历史。已核对的离线副本显示保存时间和范围。Codex 的续聊和停止交给原窗口；DSH 在设置中录入已授权的 DSH Remote 桥地址和独立令牌，随后在「原生会话」选择 DSH 和项目。DSH 续聊沿用原会话权限，停止请在原窗口操作。连接或送达不确定时可点「核对最新历史」；星引不会自动重发。
- **协作与整合**：未隔离的相同或嵌套目录串行。勾选独立工作区后，Git 项目从选定的仓库根目录及其当前 HEAD 建 worktree；非 Git 项目使用独立输出目录，原目录仅供读取。未提交修改不会自动复制。前置任务验收后，下游才接收其交付上下文。整合需显式点击，核对回合版本；普通 Git 新文件和已跟踪改动同批预检，非 Git 同名文件不覆盖。如果整合中断，可在工作结果点「只读核对整合结果」；证据不够时继续保留占用。隔离目录不会自动删除。
- **明确规则**：支持全局/项目作用域、编辑、停用和删除。在项目讨论中可用“项目决定：……”登记明确规则，并从规则页回看来源讨论。规则变化会撤销使用旧版本的待确认交接，后续调用改用当前生效规则；原始讨论仍可查看。删除标记在恢复旧备份后继续生效；原生 Codex 或供应商历史不是本地删除的一部分。
- **附件**：支持 20 MB 内的本地副本。执行输入中的文本最多提供 30,000 字符，图片交给 Codex，普通二进制只提供文件名和 SHA-256。源码构建在「目标与范围」和「执行记录」中分别列出回合投递回执；送达不代表模型实际读取。

Enter 发送，Shift+Enter 换行，Ctrl+N 新建工作，Ctrl+K 搜索。深浅色可切换，右侧动态可收起。新结果不清空正在写的草稿。默认关闭窗口时退出；启用后台后收进托盘，通过托盘菜单可停止并完整退出。

含后台预约的候选可在已暂停工作的详情中选择「预约继续」。开启后台保留后，可以为无活动或未知执行的工作预约一次；超过预约时刻 15 分钟、工作条件变化或恢复旧备份，预约会失效。预约可以取消，仍受原任务的范围、依赖和剩余额度约束。

含答复偏好的候选可在「规则记忆 → 答复偏好」打开学习，然后在总管的已完成答复下选择「更简洁」或「更详细」。同一范围最近 60 天内至少两轮反馈同向、且无相反反馈，才会出现候选。启用后只影响答复详略；当前要求和明确规则优先。可以查看原答复、停用、导出或删除偏好证据，原聊天不会被删除。

「规则记忆 → 工作方法」可查看已提炼的文件验收方法。它需要原任务的修正证据和另一项独立工作的复验，才能启用。仅在新工作匹配已验证项目、检查和运行环境时提供核对建议；出现失败反例会停止推荐。工作详情的「复盘记录」保留原始任务和回执，便于追查。

直接对总管说「循环推进 项目名：具体任务」，例如「循环推进 tech-art-daily：做一个可交互的技术美术网页 demo，可用 Blender」。项目明确就直接启动，无需打开新建表单或修改默认设置；也可以在「新建工作」选「循环推进」。星引直接启动原生 DSH 执行 Agent，随后派独立 Agent 检查实际成果；有问题就把反馈交回执行。两个角色都能使用本机原生工具，按用户授权操作。原生全权限不会在系统层阻止项目外写入。在「工作详情与操作 → 推进循环」查看当前步骤、预算和报告，在「执行记录」区分执行与独立复核。未指定推进方式时，默认仍为「单次」；旧清单任务沿用原执行路径和授权。

新版原生循环将成果和每次尝试分别记账。意外退出时，能证明尚未发送的回合会退回预占额度，重开后继续该成果；已经或可能发送的回合保留占用和预算，先核对原回执。主动暂停、完整退出及从备份恢复仍需明确继续。已有原生循环按创建时的规则运行。

**DSH 模型容量：** 所有 DSH 执行、研究和复核会话，由 DSH 已安装的提供方决定上下文和输出容量；总管的输出设置仅用于总管直接 API 调用。模型或网关自身的限制仍可能结束回合。普通原生循环使用任务总墙钟；仅显式开启弹性观察时设置单回合硬截止。新建并行工作默认勾选原生工具：DSH 可能读取工作区以外的位置。需要严格限制读取时取消该项，仍使用相同模型容量。每个分支只把登记交付的文件收为成果。

**按成果并行（预览）：** 新建「循环推进」时可勾选。在表单中指定可读的项目文本，每行填一个项目相对路径。Agent 可以为独立成果提议分支。各分支在自己的目录交付 UTF-8 文本，独立复核通过后才进入组合交付。新图使用 DSH 原生工具，执行在独立工作区写入、复核只读；命令和联网按任务及 DSH 身份授权。原项目仍需显式整合。失联的分支只保留自己的回合及所需资源，其他就绪分支可以继续。打开「工作详情与操作 → 推进循环」可查看各成果的版本、等待原因和回执，也可只调整某项成果及其下游。组合交付独立复核后，可点「结果 → 核对基线并整合产物」写入原项目；原有同名文件不会覆盖。常规「循环推进」和总管快捷输入保持原有运行方式。

**按需研究：** 建工作时可为主成果登记决定，也可在「推进循环」里为已出现的成果新增或更新决定。填写目标版本、已冻结的小样和能区分两条路线的标记。前置研究只等待所绑定的成果；并行参考只交接在派发前已核对的证据；「已有同版本范例」不增加联网或研究回合。Hub 用你指定的公开 HTTPS 资料核对正式研究证据；缺少可访问的资料时会如实记录，相关成果可在你更新决定后继续。研究面板展示来源、版本、小样结果与执行回合声明的采纳情况。

**开工前制定质量标准：** 新建成果并行任务可勾选，默认不勾选。星引先增加一项「质量标准」成果：执行 Agent 查找这类作品的优秀案例和相关理论，写出评分维度、三档表现、核对方法和达标线（`quality-standard.md`），独立复核通过后主成果才开工。之后的制作按标准卡自检，复核按维度评档；全部达标才收口，修正次数用完仍未达标的带差距清单交人工验收。联网查找需要同时勾选 DSH 原生工具，否则只凭模型已有知识并在卡片上注明。标准卡可在「推进循环」页展开查看，也可用「调整此成果」改它；它不进入组合交付，不写入原项目。此项至少多用两个回合，不与视频预览同用，简单任务不必勾选。真实对照与质量判断见[路线图](../docs/roadmap.md#standard-first)。

**弹性观察与视频预览：** 新建成果并行任务可勾选「有可核对进展时延长观察」，明确检查间隔和单回合硬截止。实际新产物可以续时，重复心跳不会续时，硬截止不会移动。也可勾选「主成果是独立视频预览」，选择项目内不超过 20 MB 的普通 MP4 和 1～60 帧。此作业需要本机 `D:\dev\ffmpeg\package\ffmpeg.exe`；确认移交后才运行，每秒提取两帧。Agent 结束后归还名额，设备与写目录等到进程树确切结束才释放。推进循环页可以核对帧数、查看回执或请求停止。PNG 和帧清单要独立复核；原视频不修改，产物仍由用户明确整合。

「循环并改进」会在必需条目通过后增加评审轮。收口报告可展开每条发现、引用、排序和搁置理由；只有核实且属于本次目标的发现能进入清单。该模式已通过本地界面与状态机验证，真实缺陷评测状态见[路线图](../docs/roadmap.md#loop-l2-local)。

在循环任务的「收口报告 → 漏检反馈」可以登记没被发现的问题。星引在同一份旧材料上比较加入候选检查前后的结果，并用同项目的另一份已完成交付核对误报。缺材料时保留提醒，等待可复验的交付。通过的「漏检检查」在规则记忆中单独列出；可查看来源、编辑后重验、停用或删除。它们只供该项目的定约和评审参考，不授予写入或命令权限。

源码构建的历史搜索可选择项目，检索本机账本里的总管对话、项目讨论和执行回复。结果能打开来源对话；旧版回执单独标注，超过 60 条匹配会提示缩小范围。

## 备份、恢复与更新

设置中“一致性备份”要求已停止并核对活动/未知执行及检查。备份含 SQLite 快照、附件/产物副本、SHA-256 清单；0.2.0 候选也包含检查输出和文件镜像。备份不含凭据。恢复前先核对所选备份的账本和全部副本，再备份当前账本。0.2.0 会一起恢复业务记录和审计事件，并合并删除标记和已领取通知。校验失败时保留现用账本；未完成工作恢复为待核对状态，不自动派发。实际工作区和 Codex 原生历史不会回滚。

手动升级：停止并核对活动任务 → 在设置做一致性备份并退出 → 将新版解压到另一个目录 → 使用相同数据目录启动。当前构建使用账本 v8；从 v7 升级会保留可恢复的 `backups/pre-native-agents-…` 副本。旧程序拒绝打开更高版本的账本；回退时用匹配的旧程序在另一个数据目录中恢复对应的升级前备份。回退到不识别质量标准的同版账本程序前，先让使用该选项的工作收口或取消。备份不含密钥，也不包含独立的 DSH 原生会话；缺少 DSH 或预览作业结束证据时保留未知，不自动重派。开发验收请使用隔离数据目录。

脱敏诊断导出到数据目录 `exports/`，仅包含版本、计数和安全状态；不包含提示正文、工作区路径、模型回复、原生 stderr 或认证头。费用未提供时显示未知；运行时间和次数限制不能替代供应商侧的金额限额。

## 目前限制

- 首版候选的已通过证据、未验收项统一维护在[路线与验证状态](../docs/roadmap.md)。不能把“有界面/接口”视为真实验收通过。
- 现有 Codex 桌面会话通过其原 owner 控制；离线、协议回执不匹配或无 owner 时界面会给出只读原因。管道握手本身不证明桌面版本或真实续聊通过。原生审批可能需要在原桌面处理。
- 大项目文件核对有上限：5000 个目录项、单文件 2 MB、合计 40 MB，排除隐藏项、依赖和常见凭据文件。达到上限会显示不完整；原生差异与命令证据另行保留。
- 原生 shell 沙箱与第三方连接器/MCP 不属于同一强制边界；本轮未证明所有原生工具对所有资源有同等隔离。
- 暂无云同步、自动更新、代码签名或开机自启。答复偏好目前只学习明确的详略反馈。Hub 使用独立 Node 子进程，窗口关闭后可随宿主留在后台；宿主进程崩溃时 Hub 停发并请求停止，不承诺脱离宿主常驻。

## 源码开发

项目依赖和源码在本目录。Node.js 24+；已验证本机 Node 26.13.1、Electron 45.3.3、TypeScript 5.9.3。

```powershell
npm ci
npm run typecheck
npm test
npm run build
```

构建后可用 `npm start` 启动。没有 D 盘，或希望先在独立数据目录试用时，可在同一个 PowerShell 窗口显式指定存储位置：

```powershell
$env:ALCOR_DATA_DIR = "$env:LOCALAPPDATA\Alcor\data"
$env:ALCOR_BOOTSTRAP_DIR = "$env:LOCALAPPDATA\Alcor\bootstrap"
npm start
```

首发核心回归用 `npm run test:release`；实际启动、保存和重开用 `npm run smoke`。另行运行 `npm run package` 制包，默认输出到 `release`，同版本文件已存在时拒绝覆盖。

模块分为 `src/shared` 运行时契约、`src/core` 纯策略、`src/hub` 账本/凭据/模型/调度、`src/adapter` 原生协议、`src/ui` React 界面和 Electron 宿主。`scripts/smoke.mjs` 用真实 Electron 验证界面；`scripts/live-*.ts` 仅在专门建立的非生产测试目录运行并使用已有授权原生账户。测试数据留在项目 `.dev/` 或 `.test-data/`，不打包。

L0 本地验收命令：`node --import tsx scripts/loop-ui-smoke.ts`（先构建）、`node --import tsx scripts/loop-experiment.ts --verify`、`node --import tsx scripts/loop-experiment.ts --fake`。真实试验需要独立开工指令，见[实验规程](../docs/advance-loop-experiment.md)。
