# P4 原生循环对照

p4.json 冻结任务、工作输入、文件名、盲评规则、模型设置、硬限制、重复次数及交错次序。工作账本和证据仅写入项目内 .dev/advance-loop/P4/，各臂使用新的项目副本、账本和 DSH 会话。

- A：现行串行原生执行和独立复核。B：成果调度，关闭研究。C：成果调度，启用已授权研究或本地范例；B、C 的工作要求及项目输入逐字节相同。
- 盲评分只接收文件名及内容，与臂、用量和耗时无关。JSON 键排序和换行不影响判定，数组顺序、字段、值类型、缺件或增加的字段影响判定。最终通过要求应用收口、全部首要产物盲评通过及无额外结果文件。首个可用成果与所有必需成果分别按第一次通过盲评的文件回执计算；另记应用完整收口时间。失败、受阻、无法核对及超时都计入样本。
- 方向性返工只记已有有效 JSON 交付、但其中已选路线与冻结判据相反，随后为同一作品重新派发的执行回合。一般格式错误、没有产出、独立复核不算路线错误。
- A/B 至少三对双方通过才比较成对交付耗时；B 的最终通过数不得低于 A，且成对节省比例中位数至少 15%。C 的最终通过数须高于 B，或者不下降且方向性返工较少。简单任务中 C 的本地范例不得发起研究回合或查网。任何确认的重复执行、过时限派发或虚假完成均否决。样本不足不推广默认值。
- 协议 v2 直接透传 DSH 原生消息、工具、输出字段与流式回执。旧 v1 曾设置工具白名单、32 次调用及 4096 输出上限；历史证据保留，不与 v2 合并评分。A/B/C 的总回合、每回合硬限制、墙钟、共享执行池和模型请求上限相同，不把研究回合藏到账本之外。

在 desktop-app 中用 node --import tsx scripts/native-loop-p4.ts --authorized 运行已获开工授权的真实对照。脚本只从已有环境凭据读取网关访问能力，隔离账本中只写本机代理占位值。观测器只统计原生请求和回执，收完分项结果后用 node --import tsx scripts/p4-report.ts <隔离结果目录> 生成 JSON 与 Markdown。只在原试验进程确定结束后使用 --resume=<该目录>；完成的分项不重跑，已有但没有结果的分项不会覆盖其输入。
